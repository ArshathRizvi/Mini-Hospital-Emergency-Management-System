SYSTEM OVERVIEW

Emergency Hospital Operational Workflow

Simulates real-world patient arrival, emergency triage, doctor consultation, treatment completion, and longitudinal medical records.

1. Patient Records (BST)

Stores patient profiles using Patient ID as the key. Provides O(log n) search, insertion, and in-order sorted traversal.

2. Emergency Queue (Queue)

FIFO triage queue for emergency arrivals. Ensures the first patient to arrive is the first to receive treatment.

3. Treatment History (Stack)

LIFO completed treatment history. Pushes completed cases; top of stack always represents the most recent treatment.

4. Visit History (Linked List)

Each patient owns a dynamic Singly Linked List of previous consultations, diagnoses, and prescriptions.

TECHNICAL IMPLEMENTATION

Key Algorithmic Decisions

BST 3-Case Deletion

Correctly distinguishes between leaf nodes, 1-child nodes, and 2-child nodes by locating the in-order successor (min node in right subtree).

FIFO & LIFO Pure Pointers

Implemented using custom QueueNode and StackNode pointers without array capacity limits or ArrayList wrappers.

Embedded Linked List

Every Patient node inside the BST encapsulates its own VisitLinkedList instance, creating a hybrid hierarchical-sequential data model.

Safety & Empty State Handling

Graceful handling of empty queue dequeuing, empty stack popping, and search misses without program crashes.
